# AI Agent 额度前端接入设计

本文描述当前额度查询接口的前端接入方式；本次仅提供设计，不包含前端实现。

## 接口

```text
GET /agent/api/quotas/current?staff_id={staff_id}
Authorization: Bearer {api_token}
```

接口详情和完整响应见 [额度后端设计](./AI_AGENT_QUOTA.md#当前额度查询)。费用字段的单位为整数 `micro_usd`，前端展示美元时使用 `value / 1_000_000`，不要把浮点展示值回传给后端。

## 建议展示

在聊天页标题栏或设置抽屉中放置“本月额度”入口。默认展示最接近耗尽的已限制维度；展开后展示所有已限制维度。

| 响应状态 | 前端展示 |
| --- | --- |
| `quota_configured: false` | 隐藏额度卡，或显示“未启用额度控制”。 |
| `quota_enabled: false` | 显示“AI 使用已被管理员禁用”，并禁用输入框。 |
| `rule.mode: soft` | 额度显示为 0 时，本次已发起请求仍可能完成；后续请求以服务端响应为准。 |
| `rule.mode: strict` | 剩余额度不足以覆盖本次最大预占时，服务端会提前拒绝。 |
| `limit: null` | 不展示该维度，因为它没有上限。 |
| `remaining > 0` | 显示 `consumed / limit`、进度条和剩余量。 |
| `remaining = 0` | 红色提示“本月额度已用尽”；输入框可提前禁用，但仍以服务端 `429` 为最终判断。 |

`reserved` 是已发起、尚未结算的请求预留量。建议在明细中单独写为“执行中预占”，避免用户看到一次提问后额度暂时下降时产生误解。

## 刷新策略

不需要 WebSocket 或 Redis。由于后端使用数据库中的已结算和预占计数，以下刷新即可得到与实际拦截一致的近实时结果：

1. 进入或切回聊天页时请求一次。
2. 用户提交消息且请求成功建立后立即请求一次，此时会包含预占。
3. SSE 收到 `done`、`error` 或被取消后再次请求一次，此时会反映结算或释放。
4. 页面保持打开时可每 30 秒后台刷新一次；页面不可见时暂停轮询。

请求进行中应保留最近一次成功数据，不要把额度卡重置为空。多个刷新请求并发时，只应用最后发出的请求结果，或使用 `AbortController` 取消旧请求。

断连后的服务端释放使用独立数据库 Session，最多可能需要 5 秒完成。因此取消 SSE 后若首次刷新仍显示 `reserved`，前端应保留输入和额度数据，并在短暂延迟后再刷新一次；不要把仍在释放的预占误报为新的额度耗尽或重复发送。

同一 `staff_id` 同时只允许一条模型请求；如果消息接口返回 `409 REQUEST_IN_PROGRESS`，保留当前输入并提示“当前已有 AI 请求正在处理中，请等待完成后再发送”。

## 格式化与阈值

- Token 使用 `Intl.NumberFormat` 分组；超过 10,000 时可辅助显示 `85.3K`。
- 费用以 `micro_usd / 1_000_000` 转换后按货币格式显示；保留 4 到 6 位小数，避免小额费用显示为 `$0.00`。
- 进度比例为 `consumed / limit`，限制在 `0..1` 后绘制。
- 比例低于 80% 为正常，80%–99% 为警告，100% 为耗尽。阈值仅用于视觉提示，不影响后端限额。

## 错误处理与权限边界

- 查询接口 `401`：按现有登录/Token 刷新流程处理。
- 消息接口 `429` 且 `code = QUOTA_EXCEEDED`：显示“本月 AI 使用额度已用尽”，并立即刷新额度卡。
- 消息接口 `409` 且 `code = REQUEST_IN_PROGRESS`：显示“当前已有 AI 请求正在处理中”，不丢弃用户输入。
- 规则禁用时，消息接口可能返回 `403 QUOTA_DISABLED`：显示管理员禁用提示。
- 当前接口允许传入 `staff_id`，仅适用于现有 MVP 的静态 Bearer Token 模式。接入 SSO/JWT 后应迁移为 `/api/quotas/me`，员工 ID 由后端身份 claim 决定。
