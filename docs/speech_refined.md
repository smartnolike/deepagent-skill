# 云资源自助服务平台
TEK Standard Cup · 8分钟演讲稿（精简版）

## 第1页：开场介绍
**预计15～20秒**

各位领导、各位同事，大家好。

今天很高兴有机会和大家分享我们在 HSBC Platform 团队交付的一个项目——云资源自助服务平台。

这个项目不仅解决了传统云资源申请效率低的问题，还通过引入 AI Agent，实现了从人工服务到智能化自助服务的转变。

## 第2页：我的角色与项目背景
**预计1分钟**

首先，简单介绍一下我们自己。

我是Kyle，Sunny是我的搭档，我们都来自HSBC Platform 团队，目前来Tek和进项目时间基本都3年了，今天我们将以 Tech SME 的角色来分享这个项目。

Sunny 主要负责自助提单系统的架构与设计、开发和上线，我主要负责 AI Agent 的架构设计以及 MCP 和 Sandbox 的集成。

在项目建设之前，客户主要面临三个问题。

第一，缺少统一的云资源申请入口，用户需要通过人工沟通或者填写 JSON 文件来提交申请。

第二，大量重复性的申请和跟进工作，占用了 Support 团队的时间，使他们很难投入到更有价值的技术工作中。

第三，缺少统一的资源管理视图，团队无法直观地了解整体的资源规模。

为了解决这些问题，我们建设了一个统一的云资源自助服务平台，让用户可以通过传统表单或者 AI 对话，自主完成资源申请，并且查看审批和部署状态。

项目于2024年3月启动，TEK 团队也从最初的一人发展到我们两人。

我们的核心目标，就是把重复性的人工工作转化为标准化的自助服务。

## 第3页：我们具体做了什么
**预计1分40秒**

明确了客户的问题之后，接下来介绍我们是如何解决这些问题的。

首先，从 TEK Standard 的角度来看，我们梳理了原有 JSON 提单流程中的资源字段和填写规则，并将其转化为 Portal 的自助申请能力。

目前，平台管理着大约130个 Project，300+个UseCase,每周处理超过200个自助申请工单。

在交付方面，我们明确了各个模块的职责边界，并通过端到端验收清单和发布顺序来支持整体交付。

接下来，我重点介绍一下这个项目的技术亮点。

对于银行这样的金融机构，引入 AI 不仅要考虑效率，更要考虑安全、合规和可控性。

因此，我们采用了双入口、统一后端的架构设计。

传统用户可以直接通过 Portal 填写表单，由 Backend 处理后续的业务流程。

而 AI 用户只需要通过自然语言描述自己的需求。

例如，用户可以告诉 AI：“我需要申请一个 Cloud SQL 数据库。”

Agent 会通过 SKill 理解业务规则，收集并补充申请参数，再通过受控的 MCP Tool 调用 Backend 的业务接口。

涉及实际写入的操作，需要经过用户确认。

这里最关键的一点是：**AI 不会绕过原有的权限校验、审批和部署机制。**

同时，我们引入了基于 GKE 的 Sandbox，将 Skill 所需的命令执行和文件操作放在隔离环境中，进一步控制执行风险。

通过这样的设计，我们既保留了传统业务流程的稳定性，也充分利用了 AI 在自然语言交互和任务编排方面的能力。

## 第4页：为客户创造的实际价值
**预计1分钟**

那么，这个平台上线之后，究竟给客户带来了什么价值？

我们主要从三个维度进行衡量。

第一，时间成本。

平均每个申请工单的处理时间，从120分钟缩短到了20分钟，减少了约84%。

第二，人力投入。

Support 团队每周投入在重复工单上的时间，从40个小时降低到了8个小时，减少了80%。

这意味着团队每周可以释放32个小时，投入到更有价值的工作中。

第三，质量和风险。

通过标准化的申请流程和受控执行机制，风险率从12%下降到了6%，降幅达到50%。

这里还有两个比较直观的业务场景。

ACE 数据处理框架的部署权限处理，从10天缩短到了1天。

Cloud SQL 数据库的申请，从48小时缩短到了2小时。

这些数据体现出，我们交付的不仅是一个新的申请门户，更是对客户原有工作流程的一次优化。

## 第5页：对TEK的价值——技术沉淀与分享
**预计1分10秒**

除了为客户创造直接的业务价值，我们也在思考，这个项目能够为 TEK 留下什么。

目前，我们已经形成了自助提单平台的技术文档包，主要包含三个方面。

第一，传统表单与 AI 对话双入口的架构设计，让其他项目能够在保留现有业务系统的基础上引入 AI 能力。

第二，Agent、Skill 和 MCP 的集成方案。通过 Skill 沉淀业务规则，通过 Agent 进行任务编排，再通过 MCP 将业务能力封装为可控的工具。
 
第三，基于 GKE 的部署和隔离执行方案，为企业级 AI Agent 的运行提供技术参考。

目前，虽然这些内容还没有在 TEK 内部开展正式分享。

但是我们的目标，是将这些项目经验转化为 TEK 可以持续积累和复用的技术资产。

## 第6页：对TEK的价值——复制与业务拓展
**预计1分30秒**

在技术沉淀的基础上，我们进一步思考，这套方案未来能够为 TEK 带来哪些新的机会。

主要有三个方向。

第一，HSBC 内部的其他项目。

目前我们的平台主要服务于云资源申请，但类似的自助服务模式，也可以进一步扩展到权限申请、资源变更，以及
其他重复性的云平台支持场景。

第二，TEK 的其他客户。对于仍然依赖人工处理云资源申请和审批的客户，我们可以将这个项目作为参考案例。

第三，其他行业。对于具备内部云平台或者开发者平台建设需求的企业，同样可以复用我们的分层架构和 AI 受控执行模式。

除此之外，我们还看到了一些潜在的机会，就是客户有意向进行 Agent Platform 的建设。

**从交付一个具体的 AI 应用，逐步拓展到交付企业级 AI 平台能力。**

目前，这个方向还处于构想阶段。

在业务拓展方面，我们可以重点对接云平台团队、Agent Platform 相关团队，以及使用 GCP 或 ACP 的应用团队

进一步识别他们的业务需求和潜在合作机会。

下一步，我们计划整理项目案例，与 AM 和 DL 一起评估潜在的适用场景，并通过内部技术分享识别更多复用机会。

我们希望通过这个项目，不仅解决当前客户的问题，也为 TEK 在云平台和企业级 AI 领域的后续业务拓展提供技术基础。
